# Evidence collection matrix

Framework 2.1.0. Use with the [contract](operating-contract.md) and [operator checklist](operator-checklist.md). This specifies external records, not promised native API field names or files.

## Locate, collect and verify

Use the required [collection layout and record formats](collection-layout.md) for every new attempt. Initialize its external root before submission and maintain category accounting during the run. Validate integrity on resumption and final handoff. Missing evidence remains a collection gap even when its absence is fully documented.

Discover the installed version's supported UI/export/CLI/API before using it. Bind each operation to current project/session/attempt/stage IDs. Prefer immutable native versions. Read-only native files are secondary evidence after resolving their real storage location; do not write application databases or fabricate native state. Scientific prompts, source inputs and generated material are separate from external evaluation.

For every capture record `evidence_id`, checkpoint, attempt/stage/session IDs, event time/time zone, captured time, archived time, P/A/H source, source locator, native IDs, version references, relative saved path, hash/size, availability/reason and collection method. Unknown capture times stay unknown. Hash copies and verify successful saving; a displayed screenshot is not archived evidence. Preserve originals, with annotated/redacted derivatives explicitly labeled.

CP2/CP3 repeat and overlap. Save transient screenshots immediately with OpenScience maximized, using the approved computer-use capability. If capture fails, retain native records and label the screenshot omission; late captures are late. Polling cannot guarantee every transient state. Check screenshot availability before phases; proceed despite a known gap only within an explicit evidence exception. Never recreate a moment and label it contemporaneous.

## Review record

Record review ID, trigger (native auto/manual/operator-assisted/unknown), queue/start/end, model/routing when available, product state/verdict, scope and version references, Plan/step association or unknown, required reads and observed success/failure/unknown, external scope assessment, finding IDs, before/after versions, affected reruns, re-review IDs and stop reason.

For each independently checked issue record finding validity (supported/unsupported/indeterminate), exact evidence, repaired/unrepaired/incorrectly repaired/unassessable, new errors and attribution. Missing before versions limit before/after claims, not necessarily finding assessment. Known-error denominators cover only independently checked issues; zero is N/A and incomplete checking cannot support recall. Acknowledgment without verified changed work is not evidence of repair.

## Reproduction record

Record attempt, target version, frontier, claim scope, captured inputs, preview, requested/completed steps, locks/gaps, comparison policy, request/completion times, native operation/receipt, logs and truncation, native outcome, each output path and expected/actual checksum/size, raw comparison results or absence reasons, retention/exportability, new-file reference and external comparison limits. Record execution reconstruction and human assistance separately.

Native fields differ by release; missing native IDs receive clearly labeled H index IDs rather than invented product IDs. Matching bytes may mean no separate content report or retained new file. Numerical comparisons use declared keys, duplicate/missing handling, units, tolerances and conclusion rules. Compare ordinary continuous indicators as ordinary numeric tables; select a specialized biological policy only if scientifically applicable.

## External storage and publication

Choose an evidence root outside this preparation repository and outside the scientific workspace. Store only genuinely available material, preserving all failed attempts and partial states. Collect usage only from actual fields; unknown is not zero. Maintain handoff and one append-only evidence index as events occur. Source tokens/credentials stay out of prompts, screenshots and share packages; preserve a private original if an explicitly authorized collection requires redaction of a sharing copy. The repository contains instructions and blank templates, not run evidence.
