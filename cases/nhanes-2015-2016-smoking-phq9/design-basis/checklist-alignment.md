# Adapting checklist v0.2 to framework 2.2.0

The [English checklist edition](OpenScience_Case_Checklist_Metrics_and_References_v0.2_EN.md) is the active reference. Its [manifest](source-manifest.json) identifies the English edition and the unchanged original retained only in the repository archive. It is an archived methodological source, including a particular simulated-marker example; its dates, scientific values and completed-tense reporting template are not defaults or evidence of this framework's success.

The [operating contract](operating-contract.md) is the prospective authority. User instructions prevail. This adaptation changes the timing of scientific commitments and the interaction style; it preserves independent checking and honest evidence boundaries.

## Section 8.2: every result category retained

The post-run collector must account for every row below with evidence/source labels, a status, or an explicit applicability reason. These are reporting categories, not extra scientific deliverables imposed on the agent.

| Original result category | New record / assessment |
|---|---|
| Product/model/environment/input type | CP0 settings and exact opening/attachments |
| All attempts; display choice | Attempt ledger including failures and selection rationale |
| Initial Plan quality | Frozen three-axis assessment of first native version |
| Plan alignment and approval | Feedback type, authority allocation, approval events and assistance |
| Execution versus approved Plan | Followed / authorized deviation / unauthorized deviation / insufficient evidence |
| Deliverable completion | Promised-content items for that stage; denominator set at approval |
| Claim traceability and support | Stage-defined claim slots: locatable and supported assessed separately |
| Initial/final scientific verification | Independently assessed available versions with reference self-validation and unresolved scope |
| Reviewer finding basis and binding | Original findings, validity, correct target versions and actual scope |
| Reviewer repair result | Known issues, verified changes/reruns, unrepaired/new errors and attribution |
| Evidence gap presentation | Actual unavailable states versus operator omissions; any assistance |
| Reproduction boundary/path | Captured input/checkpoint, context visibility, replay/reconstruction and help |
| Actual re-execution evidence | Native operation, steps, receipt/logs and real new-output identity |
| Reproduction numerical consistency | Applicable output-specific keys/fields/tolerances and raw available comparisons |
| Reproduction structure/conclusions | Duplicate/missing keys, sample counts and conclusion agreement where applicable |
| Time | Actual event intervals and separate active-time limitations |
| Human/operator intervention | Decision, environment, recovery and scientific-help events; avoid double counting |
| Optional usage/cost | Native observed fields or explicit unavailable/not-collected status |
| Supported claims and limits | Four separate assessment dimensions and unobserved feature paths |

No weighted total score is introduced. Case-specific 04 supplies scientific criteria appropriate to the question; the Plan supplies detailed commitments. Independent correctness and native reproduction consistency remain separate even if both pass.
