# Terms for conversation cases

Framework 2.0.0. Behavior is defined in the [operating contract](operating-contract.md).

| Term | Meaning and boundary |
|---|---|
| Research direction | Initial question, motivation and indispensable context; not a complete analysis specification |
| Case / protocol | Research scenario / versioned rules for conducting and assessing it |
| Run / attempt / session | Authorized case run / individual attempt, including bounded replacements / native product conversation |
| Research stage | A bounded, approved question and its commitments; an extension requires a new decision and lineage |
| Native task identity | Product-defined task ownership; sharing a session or topic does not prove it is unchanged |
| Decision allocation | Recorded assignment and limits for Plan approval, scope, extensions, recovery and acceptance |
| Plan version / approval | Exact native plan content identity / decision and native action for that version |
| Stage assessment contract | Prospective verification rules derived from the approved methods and promised content |
| Operator | External controller and assessor; actual tools and interventions are recorded, not claimed as manual labor |
| Built-in Reviewer | Native reviewing process; its verdict and actual scope are preserved separately from external assessment |
| Native auto-review boundary | Actual product trigger; association to a Plan step must be evidenced |
| Self-repair | Scientific agent identifies and repairs a problem during its own work |
| Automatic correction | Native Reviewer/correction mechanism sends and assesses remediation |
| Operator recovery prompt | External follow-up addressing a saved failure; counts as assistance, not native correction |
| Scientific assistance | Supplied methods, reference information or code affecting the scientific solution; separately authorized and attributed |
| First complete delivery | First version satisfying the stage's promised contents; it may already incorporate reviews |
| Before/after version | Exact versions around one particular revision, not reconstructed historical files |
| Captured inputs | Exact inputs to a declared generating process; not necessarily a fresh retrieval |
| End-to-end / downstream-only | Replay from declared original captured inputs / replay from an intermediate checkpoint |
| Preview / receipt | Pre-execution feasibility view / native operation result, if actually generated |
| Byte / content / scientific | Different consistency comparisons; none independently proves scientific correctness |
| Output identity / retention | Recorded checksum/size and version / availability of actual new file bytes |
| P / A / H | Product-captured / scientific-agent-generated / externally organized evidence; mixed sources are separated |

Evidence states: **captured**, **missing** (due but not retained), **unavailable** (explicitly unavailable through the product), **not_generated**, **not_retained**, **not_applicable** (with reason), **insufficient_evidence**. No observed read does not prove no read; an observed failed read establishes only that failure. Channel availability, evidence completeness and feature success are independent assessments.
