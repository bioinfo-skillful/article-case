# Working operator checklist

Copy the checklist into the external run record and mark done/pending/N/A with evidence. Keep it current, not merely read once. The [contract](operating-contract.md) defines decisions; the [matrix](evidence-collection.md) defines collection.

## Before submission

- [ ] Initialize the external evidence root using the [collection contract](collection-layout.md), blank templates and portable tool; verify identity and separate scientific storage.

- [ ] Read this case's protocol/version, opening, external assessment and frozen references; distinguish preparation from run evidence.
- [ ] Ask for and record the five-class decision allocation and its limits, including recovery/restart, Reproduction and acceptance authority. Reuse an explicit allocation only for this same run.
- [ ] Record total budget, stopping condition, restart allowance, operator-recovery allowance and replay limits; no unlimited implicit retries.
- [ ] Discover actual model/runtime/routing, permissions and native interface availability. Preserve selected settings; distinguish installed, enabled and executable.
- [ ] Choose fresh IDs and separate scientific/evidence locations; check reference-material access boundaries and record limits.
- [ ] Verify auto-review, screenshot saving and evidence entrances; maximize the OpenScience window. Resolve or explicitly document authorized capture exceptions.
- [ ] Send only the opening and legitimate scientific attachments/context through native Plan first; verify persistence and intent. Re-query uncertain submissions.

## Questions and Plan

- [ ] Inspect every visible question card against current request/message IDs, native state and persisted answers, including when the pending list is empty.
- [ ] For a current unanswered card, answer within allocated authority and submit through the native control; verify acceptance and continuation. Selected text/Finish enabled is only a draft.
- [ ] For a proved answered/stale card, retain the UI/state mismatch and use non-submitting dismissal/navigation where supported; do not press Finish/Skip just to clear it.
- [ ] For uncertain identity, investigate before submitting. Refresh after scroll/navigation/layout changes; inspect the result after each action. Disclose unintended changes and check whether anything was submitted.
- [ ] Preserve full initial Plan/version before feedback; assess validity, question coverage and feasibility. Distinguish reasonable alternatives from mistakes.
- [ ] Prepare independent stage checks from the actual proposed methods; show concrete necessary feedback to its decision owner or act within recorded delegation.
- [ ] Freeze checks against the approved version before inspecting estimates; perform native exact-version approval and verify execution start. Recheck auto-review.

## While running

- [ ] Read current execution, review, correction, permission and question state. Prefer supported event waits; otherwise poll roughly every 10–20 seconds while active, with individual waits below 60 seconds and meaningful updates at least every 60 seconds.
- [ ] Act on authorized routine permissions using current supported controls; follow tool restrictions. Escalate only the affected out-of-authority decision with a concrete explanation.
- [ ] Preserve actual inputs, Notebook execution, artifacts and version changes; capture due screenshots immediately and verify files.
- [ ] Retain each native review's scope, reads, finding, modification, rerun and re-review; preserve normal WARN/FAIL outcomes without automatically calling them product defects.
- [ ] When work stops incomplete, inspect the error and terminal states before recovery. Save the failure; send only an authorized bounded recovery prompt and label assistance.
- [ ] On finalization/revision conflict, preserve evidence; settle the failed attempt and create a fresh session only within the preallocated restart allowance. Do not combine outputs across attempts into a claimed single success.
- [ ] Maintain handoff, event/evidence indices, remaining budget and all decisions after meaningful transitions.

## Settle and decide

- [ ] Complete manifest category accounting, REPORT/HANDOFF and file inventory; run final-handoff validation and report structural errors separately from evidence gaps.

- [ ] Check both execution and all relevant review/correction activity are terminal; account for visible question cards separately.
- [ ] Freeze final versions, promised-content status and last-review coverage; independently check science and reference validity.
- [ ] Report four dimensions and any omissions; present acceptance to its allocated owner.
- [ ] Before extending, preserve the prior stage and obtain its allocated decision, then submit a genuine new research question with explicit stage/task/Plan lineage. Do not send into an active correction.
- [ ] For authorized Reproduction, freeze target/recipe/scope/comparisons, capture preview and gaps, execute natively, then save receipt/logs and genuine output identities/bytes.
- [ ] Complete CP7 with all attempts, interventions, gaps and display choices. Say what remains active or unverified; never claim an unconfigured background monitor.

## Decision allocation record

Fill before launch; blank cells are unresolved decisions, not defaults.

| Decision class | Owner: user/operator/split | Delegated limits | Escalation condition | Decision evidence |
|---|---|---|---|---|
| Exact-version Plan approval | | | | |
| Scientific scope questions | | | | |
| Research extensions | | | | |
| Recovery, restart and additional prompts | | | | |
| Final acceptance | | | | |

Also record Reproduction authorization/owner, total budget, restart/recovery/replay allowances, stopping action, settings, scientific/evidence roots and actual access limits. Ask for unresolved allocations together in a short preflight exchange; do not silently appoint the operator.

## Stage / handoff record

Record case/protocol/attempt/stage, original and latest request IDs, native task identity if available, session/project/run IDs, Plan version and approval evidence, question/estimand, assumptions/method, output commitments, comparison/claim rules and freeze time, authority changes, current execution/review/correction state, pending UI questions, evidence paths/gaps, intervention counts, remaining budget and next authorized action. Keep stage transitions and subsequent outcome records distinct so later results cannot rewrite the original commitments.
