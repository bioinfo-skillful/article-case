# 通用 Case 运行契约

版本：2026-09-12-auto-review。适用于新建 Case；按用户现行决定适配母规范 v0.2，原文与历史 Case 保持原样。术语见 [CONTEXT](CONTEXT.md)，采集入口及字段见 [证据收集矩阵](evidence-collection.md)。本文件是两份 skills 与生成模板的共同规则来源。

## 角色与可见材料

| 角色 | 工作与目的 | 可见材料 |
|---|---|---|
| OpenScience 执行 agent | 原生规划、Notebook 科学执行、自检、依据有效 findings 修订 | 01、真实附件、必要且已验证的科学环境事实、用户批准的方法变更 |
| 内置 Reviewer | 按产品原生边界自动审阅、反馈及实际发生的再审 | 题目、批准 Plan、准确受审版本及科学依赖；范围和读取由真实记录证明 |
| 外部操作/人工审核 | 三轴 Plan 初评、操作与同步留证、独立科学核验、Reviewer 效果评价 | START、02–04、母规范、独立参考与全部允许采集的证据 |
| 用户 | 准确 Plan 版本审批、实质科学变更决定、结果验收与展示选择 | 外部已完成的初评、具体问题及对应版本证据 |

参考代码、参考值、已知错误清单留在外部。官方科学示例/作者结果是待核验的参考，不是无需检验的真理。独立参考从任务、批准方法和确切输入推导，并用小样本或另一实现验证自身；重复调用被评代码只证明可重跑。参考发现一旦反馈给系统，记录为科学帮助。

P=产品自动捕获，A=OpenScience 内部生成，H=外部人工整理。原日志是 P，外部建立的关联索引是 H；两者分开。外部统一署“人工审核”，记录实际工具和时间，不编造身份或人手劳动。目录分开不等于访问控制；每次确认参考材料的实际可见范围。

## CP0：事前条件

冻结科学任务、允许输入及数据获取/生成规则、公开输出要求、独立核验方法、字段/ID/容差、声明槽位、预算与停止条件。总预算包含新会话重启、计划修订、Reviewer 修订及 Reproduction 尝试；上限按本题确定。无文件时保留提示词和规则，不预造数据。

保留用户选择的模型、环境与其他设置。新主流程在提交前启用 auto-review，并在新 session 创建后、批准 Plan 启动科学执行前再次读回有效状态；配置快照保存到本次尝试。核对实际 Reviewer 路由，可得时保存，不为一个 Case 擅改全局路由。未能确认有效开启则处理为启动条件未满足，不能声称已开展自动审阅实验。

先验证必要的原生取证入口和截图保存。只检查本题所需能力，静态/非计算任务可将 Notebook 项记 N/A。计算任务沿 OpenScience Notebook 路径执行，保留实际输入→run→Artifact Version 关系；导出脚本可交付，但不能替代执行证据。

## CP1：原生 Plan first 与用户审批

Plan first 是逐消息发送动作。用原生菜单，或经当前安装版验证能传递等价原生意图的 CLI/API；普通“make plan”文字不算。提交后核验准确用户消息的 ID、session、时间和规划意图。0.28.0 已观察字段为 `turnIntent: "plan-first"`，升级后以实际接口为准。

保存完整原生 plan_v1、附件/引用、版本和时间，再冻结三轴初评：科学合理性、公开要求覆盖、与预设建议流程的关系。截图/摘要不能替代原文。合理替代不记错误；只提出科学错误、明确要求遗漏和实际执行阻碍，不强制纯优化或隐藏偏好。

外部先完成初评与具体反馈草案，用户批准准确版本后才操作产品审批并核验执行启动。反馈获准不等于新版执行获准；命令权限不等于科学 Plan 审批。审批等待与科学帮助分别记录。

科学 Plan 包含科学数据、方法、参数、计算和必要交付，不承担外部截图、评分、token、归档或 Reviewer 编排。原始输入、代码、参数、种子与科学重跑说明仍是合理科学输出。

## CP2/CP3：执行与 auto-review 交错循环

CP2 是执行留证位置，CP3 是实际审阅事件的留证位置，二者可反复交错；不是“全任务初版完成后才开始 Reviewer”。

1. 按产品原生边界观察审阅。记录它与 Plan step/run 的真实关联；关联不可得则标未知。不拆 turn、强制逐 step 审阅或追加登记轮次来制造自动触发证据。
2. 输入首次使用时及每次变化时保存版本；保留实际代码/单元顺序、run 状态、日志、输出绑定。原生不可变版本优先，活文件复制前后校验源哈希；变化中副本只作带时点的部分快照。
3. 每轮保存触发方式、queued/start/end、Review ID、scope、受审版本及读取证据。题目、Plan、代码/数据/表/图/报告的必需范围由科学任务决定。ID 非空、同名路径或执行 agent 的回执均不能单独证明 Reviewer 读到了正确科学内容。
4. 保存 findings 原文→所指版本→修订后版本→受影响 run→再审的链。评价某轮修复用该轮确切修订前版本；版本不可得则相关修复/新错误不可评估。
5. 首个完整交付版按首次完整形成的时点留证，并记录此前/同期审阅；它可能已被 auto-review 改过，不能称全局未经审阅基线。不要关闭 auto-review 为制造该基线。
6. product_verdict 与 human_scope_assessment 分列：确实错版/不可读为审查受阻；读取证据不可观察为证据不足；仅清单/哈希 PASS 只支持该范围。原生 verdict 原样保留。
7. 有依据的科学发现由执行 agent 在新版本中修订并重跑；实质方法/范围变化交用户决定。普通已授权修订不逐轮重复问权限。发生补充交接或手动审阅时，标明干预方式和范围，不计作无干预原生自动审阅。

独立评价按问题去重并关联 findings：成立/不成立/无法判断；发现且正确修复、发现未改、修错、未发现、误报改坏、误报未改坏、合理建议、不可评估。修复归因分别记录 OpenScience、人工提示后修复、人工直接修复。已知错误分母只限实际独立核验范围，n=0 写 N/A；未穷尽错误时不报召回率。无自然错误或未发生修订时，只描述审阅流程，不能声称已验证纠错能力。可选 probe 仅在明确启用后独立登记。

## CP4：终态与独立验收

分别读取 execution 和 review 生命周期。execution idle 或 CLI completed 不代表 Reviewer 已结束。末轮审阅是否触发、其终止原因、实际覆盖的最终版本，以及未审部分都记录；未触发不能补写成已审。

二者均终止且文件稳定后冻结最终版；受阻或按预算终止也可归档，但不称 Reviewer-approved。核验输入规范、方法、结构、数值/结论、图和报告，并分别评估交付完整性、声明可定位性与科学支持。原生 PASS 和符合批准 Plan 均不能替代正确性。向用户提交已完成的验收意见，保留后续用户决定。

## CP5/CP6：原生 Reproduction

CP0 先定起点、目标版本、输入范围、环境、执行/补救预算与比较规则；CP5 保存当前原生起点预览、实际待执行步骤、环境锁和缺口。主展示选择 original captured inputs / end-to-end，含义限于所声明生成过程，不自动包括重新联网取数或整项研究。checkpoint 起点单列 downstream-only，不替代上游复现证据。

关键依赖缺失阻断正式执行；非关键元数据缺口记录后按实际条件限定主张。预览通过仅代表可尝试，CP6 必须有正式执行证据。记录实际环境恢复、内核/工作区和旧结果可见性；逻辑目录与口头约束不能证明隔离。

保存正式 receipt、原生日志、逐输出 expected/actual checksum 和大小，并分别记录 byte/content/scientific 的原始结果、是否生成、适用性与原因。字节匹配时可能未生成 content 报告；scientific=None 是未选领域策略，不是 scientific PASS。具体以本次原生记录为准。

新输出拆成身份、保留状态、可导出状态。原生保留时按原字节收集再独立比较；未保留则保存 actual checksum/大小与证据，不能复制原文件冒充重跑文件。原生比较发生在操作方导出之前并不构成违规。没有新文件副本时，明确外部比较的实际范围，不能称独立重跑文件比对。

普通模拟连续指标按 marker ID 对齐、查重/缺失、预设数值容差及结论规则；不因 UI 提供差异表达选项就把 marker 当基因。原生领域策略只在科学任务适用且明确配置时使用。科学正确性与两次产物一致性单列；错误结果也可能一致复现。原生执行失败、代码重建、外部普通 Notebook 复跑和人工补救分别记录，后两者不能替代原生 Reproduction 成功证据。

## 指定会话错误：全新尝试

用户指定 finalization / revision conflict 不做本计划内排查、根因分析或修复，也不是 skills 升级验收条件。遇到时留存 session ID、原始错误、相关版本及当前可得证据；核对旧尝试是否仍活动，按本 Case 授权范围停止旧尝试并确认终态，避免并行重复执行。

在 CP0 预设总预算/重启额度内创建全新 session，重新核对配置，从原生 Plan first 开始，用户批准新 Plan 的准确版本后执行。沿用已冻结的科学条件，旧 checkpoint/输出不作为新主路径的起点；各次分别登记，不拼接成一次“完整成功”，重启不增加独立 Case 数。额度用尽则保存中止状态及已完成初评，交用户决定是否续额。此规则不要求重启整个应用。明确要求复用历史 Case 时保留其冻结协议并记录差异，旧 Case 特例不覆盖新默认。

## CP7：归档与范围声明

按证据矩阵在事件发生时收集，02 最后整理，不能等终场重造瞬时状态。保留全部尝试、失败和展示理由；时间重叠用并集，实际人工活跃时间未知写 missing。可选用量只收真实原生字段，区分累计和增量，不为用量拖延流程。

“通道可收集”“该次证据完整”“该功能成功”分开。材料齐全不等于科学正确；文档验证不等于真实 Case 完成。平行展示、注错 probe 或缺陷排查不由本契约自动授权。
