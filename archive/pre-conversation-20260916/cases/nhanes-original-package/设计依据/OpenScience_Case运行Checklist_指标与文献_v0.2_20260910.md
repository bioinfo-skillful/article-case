# OpenScience Case 运行 Checklist、量化指标与参考文献

版本：v0.2；日期：2026-09-10。状态：执行模板，所有结果待填；尚未运行，不构成产品能力已验证的声明。

适用：1–3 个 case，作为预印本的实证评价，重点展示工作流与证据链，同时分别核验正确性、可追溯/可复现性、Reviewer 检查修订质量。按没有独立 benchmark 的情况设计；如后续增加 benchmark，单独报告其任务、条件与得分。

案例默认允许仅提交提示词；有文件才在提交前冻结文件。采用 plan-first：先保留并评价第一版计划，再由人工审批和必要修改，使执行计划与预定建议流程对齐，然后开始分析。最终结果应描述为“人工审批/对齐计划后的执行表现”；第一版计划评价单列。

本清单保留 CP0–CP7。检查点是留证位置；CP1 的人工计划审批是本研究明确采用的操作步骤，其他检查点不要求新增产品审批弹窗。Reproduction 的实际入口与能力以测试 release/commit 为准。

配套材料：原文提及 `OpenScience_Workflow任务设计_v0.1_20260910.md`，本次未取得其内容，也未取得预印本全文。以下保留原清单的“两组、12 个 marker、五类交付物”作为 Case 01 模板，不推定其他任务参数。实际提示词与建议流程应在 CP0 填齐并冻结。

## 1. 评价定位与执行首页

### 1.1 主张—证据映射（在 CP0 前确定）

以下是拟检验的案例级主张，结果允许为部分支持、不支持或证据不足。产品公开说明用于选择检验对象，不能代替运行证据。

| 拟检验主张 | 最直接的证据与判定 | 结果边界 |
|---|---|---|
| 第一版计划能提出合理且完整的方法 | 未经人工修改的 plan_v1，与预先冻结的计划评价表逐项比较 | 分开报告科学合理性、要求覆盖和建议流程一致性 |
| 经人工审批/对齐计划后，案例产物在已核验范围内正确 | 实际执行与批准计划的对照；作者参考实现；数值、图表、声明核验 | 正确性归于所述人机协作条件，不代表自主端到端成功 |
| 确切产物版本可追溯到生成过程 | artifact ID、版本、校验和 → 实际输入、代码、参数及执行记录 | 作者补出的关系不能计为产品自动捕获 |
| Reviewer 检查及修订与具体版本绑定，且有正确依据 | finding 原文及指向版本 → 作者核实 → 修改及重跑 → 复核；另查新错误 | 无初始错误时可评价 finding 支持情况与流程，不能证明检错或修复能力 |
| 选定产物的生成过程在声明条件下可重新执行 | 新进程/内核、真实执行、新输出、逐字段差异及结论比较 | 记录重放、代码重建和人工补救分别注明；错误也可能一致复现 |
| 缺失证据被明确呈现 | 产品实际显示 unavailable 的位置、缺口内容及人工补齐记录 | 未遇到缺口时记“本案例未观察”，不推断普遍缺口识别能力 |

上述追溯与审核检验对象参考 [OpenScience README](https://github.com/aipoch/open-science) 中 immutable artifact、provenance、version-scoped Reviewer evidence 的说明。持久内核/项目是运行条件；若没有专门的重启恢复检验，不据本案例声称已验证持久恢复能力。

## 2. 按时间执行的 Checklist

### CP0：运行前冻结

- [ ] 冻结完整初始提示词、交付要求、参数、环境、预算及终止规则；记录其是否明示建议方法，不事后把方法提示从输入中删去。
- [ ] 若有用户文件，保存原件、版本/来源、SHA-256，数据字典有则保存。无文件填“初始输入文件：N/A，仅提示词”，不要求预先生成 CSV、代码或种子文件。
- [ ] 冻结后续数据生成/获取规则：谁生成、允许来源、结构、模拟参数与随机性要求；任务不涉及数据则相关项 N/A。若种子等未预指定，记录其将在何时确定，不根据结果反复挑选。
- [ ] 冻结作者侧“建议流程”和第 3 节初版计划评价规则；明确哪些要求已在提示词公开、哪些仅用于作者评价/后续流程对齐。隐藏偏好不作为初版计划错误。
- [ ] 冻结作者参考实现及其独立验证方法；已有固定输入时可预先计算参考值。仅提示词且数据待生成时，先冻结参考方法，后在确切数据冻结后计算参考值并记时点。
- [ ] 参考代码、参考数值、作者问题清单不给执行 agent 或内部 Reviewer。计划修改可以提供方法建议；若意外暴露参考答案，登记暴露范围及对应尝试。
- [ ] 冻结输出字段、ID 对齐、容差、结论规则和声明槽位。Case 01 使用第 4 节模板；其他 case 在观察结果前替换为自己的规则。
- [ ] 冻结第 6 节复现边界：生成材料、是否包含数据再生成、原会话/旧数值可见性、环境依赖操作与人工补救上限；登记是否启用独立错误探针。
- [ ] 开启可获得的执行、时间与用量记录；建立全部尝试台账，调试重跑不覆盖旧记录。

检查点：事前冻结“实际已有的输入和评价规则”，运行中首次形成的数据/代码按首次形成时点留证。不能把运行后材料标成预先冻结。

### CP1：初版计划评价、人工对齐与审批

- [ ] 发送完整任务，并明确 plan-first：先交付计划，等待人工批准后再开展实质分析。记录批准前允许的输入检查/元数据查看范围；不把已执行分析后整理的方法说明当作初版计划。
- [ ] 在任何人工反馈前保存第一版计划 `plan_v1` 的全文、版本、时间、实际可访问上下文。缺显式计划如实记缺失；若提前执行，保留记录并记流程偏离。
- [ ] 用第 3 节表独立评价 plan_v1；先冻结评价，再向 agent 反馈。后续修正不得回填改善初版判定。
- [ ] 人工对照预定建议流程审阅、修改；保存每条反馈、逐版计划、差异和理由，区分纠正科学错误、补充遗漏、统一流程及表达调整。
- [ ] 保存最终人工批准事件、批准人、批准计划版本 `plan_approved` 及其与建议流程的对应。无修改也记录批准及人工审阅时间。
- [ ] 批准后启动分析。执行中确需改变科学流程时，记录原因、重新审批及受影响步骤；禁止为维持“一致”而隐去合理偏离。

检查点：第一版计划质量与人工对齐后的执行表现分开评价。批准本身计计划审批活动；实质方法反馈计科学帮助。前者不自动等于一次纠错，后者不能仅归为权限操作。

### CP2：初始分析完成、Reviewer 修正前

- [ ] 对运行中新生成/获取的数据，首次用于分析时保存确切字节、SHA-256、来源、生成代码/命令、实际参数、种子与环境；核验其是否符合任务和批准计划。
- [ ] 数据后续变化形成新版本，记录原因及受影响重跑。数据生成不合要求是正确性问题；在错误数据上算得正确不能使案例整体通过。
- [ ] 保存实际执行代码、命令/Notebook 单元顺序、开始/结束时间、退出状态、stdout/stderr 或产品等价记录。
- [ ] 保存审核前初始结果表、图、报告及校验和；分别标识数据生成、分析执行与文件整理动作。
- [ ] 对照批准计划记录实际设计、方法、参数、输出及偏离；保存依赖安装、报错、重试和变更原因。
- [ ] 若产品仅在审核后暴露产物，注明初始快照不可得，不事后重建一个“初始版本”。

检查点：区分“生成代码”“真实执行”和“事后汇总”。运行中生成的输入也必须可追溯，不冒充用户附件。

### CP3：Reviewer 检查与修订

- [ ] 保存检查触发方式、时间、模型、提示词和实际可访问文件/上下文；记录是否能看到批准计划。
- [ ] 保存每条 finding 原文、ID/人工编号、所指产物确切版本、依据与状态；区分实质问题、建议、证据不足。
- [ ] 保存修改前后代码/数据/表/图/报告的版本及修改者；数值或数据变化必须保存对应重跑。
- [ ] 保存复核及终止原因；无 finding、无修改、超限、报错均如实登记。
- [ ] 作者在不向内部 Reviewer 提供答案的条件下核实 finding、初始问题、修复及新引入错误；采用第 5 节核心质量表。若作者向执行系统反馈问题，另记人工科学帮助及其效果归属。

检查点：内部 pass 不等于正确。审核前后快照缺失时，相关修复/新错误判定为不可评估。正常案例没有初始问题时，修复数分母为 0，填 N/A；不能表述“Reviewer 全部检出/全部修复”。

### CP4：最终原产物冻结与作者核验

- [ ] 按第 4 节检查并冻结五类交付物（其他 case 使用预定清单），记录 artifact 版本和校验和。
- [ ] 核对最终数据版本、输入校验和、批准计划、实际执行代码和交付脚本之间的关系；事后整理脚本须标记来源并核查等价关系，不能替代缺失执行记录。
- [ ] 作者用已验证的参考实现核对数据/任务符合性、方法、结构、数值及图表；对初始和最终版本分别记录可获得的核验结果。
- [ ] 逐项填写固定声明槽位的存在、可定位、支持判定；定位到错误代码不等于声明正确。
- [ ] 指定 Reproduction 目标 `results.csv` 的确切版本及生成输入；不使用会变化的“最新文件”。

检查点：原结果正确性与复现一致性分别报告。即使原结果错误，仍可继续测试复现并披露错误；作者核验后如再修正，另存版本并明确展示的是哪一版。

### CP5：启动 Reproduction

- [ ] 按 CP0 冻结的第 6 节边界保存请求、目标版本、允许材料清单、环境和上下文条件。
- [ ] 保存产品识别的输入、代码、参数、依赖与缺口；逐项标 P/A/H，人工补齐前后的状态都保留。
- [ ] 使用新进程/内核及独立输出目录；记录是否继承会话、项目记忆或未保存变量，旧结果数值是否可访问。
- [ ] 记录同机器同环境、同机器新环境或异机；实际不能隔离时写清限制，不能统称独立或跨环境复现。
- [ ] 逐次记录直接重放/代码重建、自动依赖处理和人工补救，不用后一次成功覆盖首次失败。

### CP6：复现结束与比较

- [ ] 保存从已冻结分析输入到新结果的真实执行证据、实际代码、退出状态及新文件校验和；若声称包括数据再生成，另核验生成步骤。
- [ ] 对 Case 01 核对 12 个 marker 集合、唯一性、行数及各组实际分析样本量；重复/缺失 ID 单列失败。
- [ ] 五个数值字段分别比较并报告 x/12，辅以总计 x/60；缺失、非有限数值、超容差数量分别登记。
- [ ] 保存逐字段差异、最大绝对误差、非零参考值的相对误差及 12 项校正后结论标记比较。
- [ ] 保存每次复现的执行路径、帮助情况、时间、用量、终止原因和未解决缺口。

检查点：真实重执行、结构完整、必要数值在容差内、样本量与结论一致均满足，才描述为“该案例在所述条件下复现一致”。资料不足时为未能判定，不默认成功或将其混作数值不一致。

### CP7：论文材料封存

- [ ] 保存全部 case、尝试及展示选择的台账；按案例展示结果，不用单元格数扩充样本量。
- [ ] 正文图表引用具体文件和版本；最终结果表含 P/A/H 来源及 missing/unavailable/N/A。
- [ ] 保留 plan_v1、初版评价、人工反馈、批准计划及后续偏离，正文明确人工审批/对齐条件。
- [ ] 正常运行与可选错误探针分别封存；若无 benchmark，正文按案例证据范围表述。
- [ ] 清除凭证后检查证据包仍保留必要方法信息；留出未验证贡献和失败模式，不据完整人工材料包推断产品内置能力完整。

## 3. Plan-first：第一版计划的评价与人工对齐

### 3.1 先冻结建议流程

CP0 填写：数据来源/生成要求 → 质量检查与预处理 → 研究设计/比较方向 → 分析方法与参数 → 多重比较/结论规则 → 表/图/报告 → Reviewer → Reproduction。各步骤允许的替代方案、必须统一的参数及理由一并写明。不同案例使用自己的流程；同一 case 的重复尝试使用同一版本，变更另记。

仅在提示词公开的任务要求或科学有效性方面评估初版缺陷。作者未公开的偏好可用于后续统一流程，但不把偏离偏好称为错误。人工批准计划也须满足科学要求，不能仅以“符合建议流程”作为正确性证据。

## 4. 正确性与交付验收细则

本节为 Case 01 两组、12 个 marker 模板。CP0 补齐实际列名、样本量规则、检验族、独立/配对设计、单双侧、校正范围/方法及阈值（含 `<` 或 `<=`）；不在本次修订中假定这些尚未提供的任务细节。

### 4.1 五类交付物最低内容

| 交付物 | 计入完成数的最低要求 |
|---|---|
| `analysis.py` | 可读的实际分析实现或可执行整理版；明确输入/输出、预处理、比较方向、统计方法、校正、随机性和入口；与实际执行版本的关系可说明。运行是否成功及方法是否正确另核验 |
| `results.csv` | 可读；12 个预定 marker 唯一且齐全；有各组有效样本量、mean_A、mean_B、B−A、原始 p、校正 p、结论标记，或 CP0 定义的等价列名；应为有限数值的单元格有效，不只保存屏幕显示的舍入值 |
| `comparison.png` | 可打开且可辨识；明确 A/B、marker、坐标轴/单位、比较方向；所画数值及方向与结果表一致；如有误差线或显著性标注，给出定义且与预定方法一致 |
| `report.md` | 包含任务/数据来源、设计与方法、校正/阈值、核心结果和模拟数据限制；五个声明槽位均有明确内容，关联所用表/图版本；声明支持与否另判 |
| `README.md` | 列出文件、来源/生成方式、所需环境/依赖、实际运行入口与输出位置、必要随机性/参数及限制，使读者知道如何执行和检查 |

逐文件填“满足 / 不满足 / missing”及理由，报告 x/5。内容完整与科学正确分别记录：内容齐全的报告仍可能存在错误声明。若任务在 CP0 已改变交付类型，预先另定分母，不能运行后放宽要求。

### 4.2 五个声明槽位的判定单位

| 固定槽位 | 一个槽位覆盖的内容及完整判定条件 |
|---|---|
| 样本量 | 两组实际进入分析的数量；若不同 marker 因缺失有不同 n，覆盖全部 12 个 marker 的 n_A/n_B。配对设计还须覆盖有效配对数 |
| 比较方向 | 明确差值为 B−A（或预定方向）；如报告对 marker 的方向作总结，逐一核对所声明 marker 的符号和组别，不只核对公式文字 |
| 检验方法 | 与数据设计对应的检验族、独立/配对、单双侧和关键参数；覆盖实际使用的全部方法分支 |
| 校正方法 | 校正算法、校正的检验集合/家族和阈值；与实际代码和表对应 |
| 显著性总结 | 以全部 12 个 marker 的校正后标记构成一个完整声明槽位。须明确显著集合及其余不显著者，或提供完整 12 项分类；只提部分 marker 记“部分存在” |

每个槽位分别填：存在状态（完整/部分/缺失）→ 可定位程度（完整/部分/不可定位）→ 支持判定（支持/矛盾/无法判断/缺失）。

- 可定位 x/5：仅“完整存在且整个槽位有确切版本证据”计 1。部分存在或仅部分可定位均不计 1，另列说明；分母始终为 5。
- 支持判定：“支持”需完整内容均有证据支持；任一实质断言与证据矛盾则“矛盾”；未见矛盾但内容或证据不完整则“无法判断”；完全未作声明为“缺失”。四类数量之和为 5。
- 证据是否支持报告，与实际方法是否符合任务分别核验。例如报告准确描述了错误方法，可对“用了什么方法”判支持，但原结果方法核验仍不通过。
- 显著性槽位另外附 12 项明细；槽位是一个汇总判定，不能用汇总掩盖个别错误。

### 4.3 作者参考计算与原结果核验

参考实现应从任务/批准方法和确切输入独立编写，不复制被评代码或从目标结果拟合答案。至少保存一种独立校验：用可手算的小数据核验均值、差值和相应统计公式/校正步骤，或用另一独立实现交叉核验。记录覆盖范围与共享依赖；同一库重复调用不构成完全独立验证。参考实现的自检和差异文件保留在作者核验目录。

仅提示词案例的数据尚不存在时，CP0 冻结参考方法；数据形成后检查生成规范并计算参考值。相同种子不保证不同生成实现得到相同数据，因此以实际冻结数据核对分析数值，同时单独检查数据生成是否符合任务。若参考实现自身尚未验证，不能仅凭“作者生成”给出通过。

| 核验层面 | 记录内容 |
|---|---|
| 输入/生成规范 | 文件/来源、结构、样本设计、模拟参数、随机性是否满足任务；数据版本是否对应本次执行 |
| 方法与计划 | 科学合理性、与任务符合性、与批准计划的一致/获准偏离；不因人工批准而跳过科学核验 |
| 输出结构 | ID、行数、列名、有效样本量、缺失/异常值 |
| 数值与结论 | 按预定字段及参考方法比较，记录差异；方法不同先判断可比性与合理性 |
| 图表与报告 | 方向、标签、数值及声明是否与正确的结果对应；模拟数据不支持真实生物学发现 |

每层可填：通过 / 不通过 / 不可比 / 未评估 / 证据不足，并给依据。已开展核对但方法不能直接比较为“不可比”；未做核对为“未评估”；记录不够判断为“证据不足”，三者不能互换。

综合状态规则：任一已证实错误则“不通过”，并保留其他未决项；否则有未评估/证据不足则标相应未决状态；否则仍有必要数值项不可比则“不可比”；全部适用层面通过才记“通过（在预定核验范围内）”。初始版与最终版分别报告。合理替代方法造成数值不可比，不直接等于科学错误。

### 5.1 可选：单独标识的受控错误探针

默认不纳入正常 case；是否启用在运行前登记。若自然运行无错误，它可增加一条限定条件下的检错/修复观察；不启用时写“未观察到自然错误，检错/修复能力未在本案例验证”，不由 pass 推导能力。

### 6.3 数值与结论比较

Case 01 保留 v0.1 的预设容差：`abs(new-old) <= 1e-10 + 1e-6*abs(old)`，仅用于预期有限的未为展示而舍入的文件值。NaN/Inf、缺失、非数值均不算一致。若文件只保留舍入值，如实说明精度限制。

| 字段 | 固定分母 | 一致 | 超容差 | 缺失/异常 | 最大绝对误差 | 最大相对误差（old 非零） |
|---|---|---|---|---|---|---|
| mean_A | 12 | 待填 | 待填 | 待填 | 待填 | 待填 |
| mean_B | 12 | 待填 | 待填 | 待填 | 待填 | 待填 |
| B−A | 12 | 待填 | 待填 | 待填 | 待填 | 待填 |
| 原始 p | 12 | 待填 | 待填 | 待填 | 待填 | 待填 |
| 校正 p | 12 | 待填 | 待填 | 待填 | 待填 | 待填 |
| 合计（辅助汇总） | 60 | 待填 | 待填 | 待填 | 不跨字段代替明细 | 不跨字段代替明细 |

每字段三类数量之和为 12；误差仅在可比较有限数值上计算并注明数量，无可比较值则 N/A。按固定 marker ID 对齐；重复 ID 不任取一行，该 marker 比较记异常，并单列结构失败；额外 ID 也单列失败。

marker 集合、各组有效样本量须严格一致；12 个校正后结论标记按 CP0 的阈值和边界严格比较，同时检查输出标记是否符合各自 p 值。数值在容差内但结论变化，仍判不满足复现一致。结果表的严格一致可能共同复制原始错误，原正确性核验始终单列。

|---|---|---|---|---|---|
| 待填 | 权限操作 / 环境维护 / 计划审阅审批 / 科学帮助 / 表达格式帮助 | 如：无修改批准、指定校正方法、直接改代码、补数据文件、改标题 | 待填 | 待填 | 待填 |

一次连续围绕同一目的的人工动作计一个事件，可有多个类别标签但总数不重复计。不同目的/时间的反馈分别计；记录分类计数可能重叠。提供初始任务本身不计纠错。仅建议格式与直接改统计代码必须可区分；同一人的重叠活跃时间不重复计，多人的时间按人分钟汇总并注明。作者独立核验属于评价劳动，不计入执行系统帮助；一旦将核验结果反馈给系统，则另计科学帮助。活跃计时缺失不记零。

### 7.3 可选成本与附加记录

用量/费用按执行、Reviewer、复现及失败尝试分开记录，注明实际模型、运行日期费率与供应商计费单位，避免 reasoning tokens 重复计数；无法计价则只报用量。另可记修正轮次、五类必要依赖记录覆盖及作者定位证据的活跃时间。没有匹配条件对照，不称节省时间或提升准确率。不得用日志行数、60 个单元格或多条 finding 制造独立样本量。
