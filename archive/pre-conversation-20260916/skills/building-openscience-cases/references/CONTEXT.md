# OpenScience Case 术语

共同规则见 [运行契约](operating-contract.md)，记录格式见 [证据收集矩阵](evidence-collection.md)。

| 术语 | 定义及边界 |
|---|---|
| 科学题目 / 科学 Plan | 公开研究任务 / OpenScience 产生的原生计划；外部初评、反馈和用户批准是不同记录 |
| 人工审核 | 外部操作、独立核验、整理和评价的统一角色名；不虚构手工劳动或身份 |
| Reviewer | OpenScience 内置审阅角色；原生判断与外部范围/正确性评价分列 |
| 原生自动审阅边界 | 产品实际触发 auto-review 的执行边界；与 Plan step 的关联必须有事件证据 |
| 首个完整交付版 | 首次形成完整交付的版本，可能已受运行中自动审阅影响 |
| 修订前版本 | 某次修订前的准确版本，仅用于该次局部前后评价 |
| 历史“初版” | 旧协议中审核前冻结的版本；新主流程不承诺有全局未经审阅初版 |
| 原始捕获输入 | 所声明生成过程起点的确切输入；可以是代码内常量，不自动包括重新抓取来源 |
| end-to-end | 从声明的原始捕获输入到指定目标，覆盖范围内全部必要生成步骤的重执行 |
| downstream-only | 从中间 checkpoint 开始，只支持其下游步骤的复现结论 |
| 起点预览 | 正式执行前的输入、步骤、环境及缺口检查；不是执行成功 |
| receipt | 产品保存的正式执行结果记录；原生字段和失败时是否生成按实测记录 |
| byte / content / scientific | 字节一致 / 解析内容比较 / 适用领域策略比较；都是两次产物比较，不替代独立正确性 |
| 输出身份 / 文件保留 | actual checksum、大小等记录 / 是否能取得该次新文件字节；两者分别判断 |
| 独立科学核验 | 从任务、确切输入、批准方法及已验证参考方法判断正确性；参考本身需验证 |
| Case / session / attempt | 一个研究任务 / 产品会话 / 具体尝试；重启、审阅轮次、复现和 probe 不增加独立 Case 数 |
| P / A / H | 产品自动捕获 / OpenScience 内部生成 / 外部整理；来源属性不等同角色或正确性 |

记录状态：missing=应收未收；unavailable=产品明确显示的缺口；N/A=不适用且说明理由；未生成=本次原生记录没有该报告；未保留=输出有执行身份但无保留文件。未观察到读取属于证据不足，不证明没有读取；观察到文件读取失败才可称不可读。
